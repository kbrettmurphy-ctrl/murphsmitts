# MurphOS Design Language

MurphOS should feel like software built specifically for Murph’s Mitts.

## Core Philosophy

MurphOS should answer:

> What is Brett trying to do right now?

Not:

> What database field needs editing?

## Design Rules

- Reduce clicks.
- Prefer workflow actions over generic editing.
- Keep common actions available from the Orders list.
- Use the full Order Detail page for exceptions and deeper edits.
- Every modal should ask as few questions as possible.
- Avoid unnecessary confirmation dialogs.
- Do not make order cards taller unless there is no better option.
- Preserve visual clarity on mobile.
- Keep the interface calm: navy, cream, red accents, minimal noise.
- Do not confuse workflow status indicators with lace color indicators.
- Do not add features just because they are possible.

## Interaction Rules

- Normal tap/click opens details.
- Long press/right-click should reveal workflow actions when used.
- Existing communication actions should remain easy to reach.
- Destructive actions should be deliberate.
- Workflow completion should give clear feedback.

## Tone

MurphOS should feel:

- practical
- fast
- confident
- purpose-built
- lightly polished, not flashy
